# kanto-stay-search

関東圏（東京・神奈川・千葉・埼玉・茨城・栃木・群馬、＋静岡東部）で、**金曜チェックインの1泊・大人4名・1部屋**で泊まれる宿を、**1部屋あたりの総額（税込）**で比べるための静的Webアプリです。

- バージョン: 0.2.0（`package.json` と同じ）
- 状態: 開発中
- 最終更新: 2026-11-24

## 目的

「1人あたり料金」ではなく「1部屋あたりの総額（税込）」で宿を比べられるようにします。

検索条件のうち、画面で選べるのは**チェックイン日とエリアだけ**です。人数・部屋数・予算は固定で、変更できません（従来の熱海ウォッチの条件を引き継いだ値です）。

| 条件 | 値 | 画面で変更できるか |
|---|---|---|
| チェックイン日 | 選んだ日（最初は直近の金曜日）・1泊 | できる |
| エリア | 東京・神奈川・千葉・埼玉・茨城・栃木・群馬・静岡東部 | できる |
| 大人人数 | 4名 | できない（固定） |
| 部屋数 | 1部屋 | できない（固定） |
| 予算 | 1部屋総額10,000円以下（税込） | できない（固定） |

固定条件は画面の「条件」の欄に「固定条件」として常に表示されます。宿データも、この固定条件（大人4名・1部屋・1部屋総額10,000円以下）で確認・取得する前提です。

いちばん大事なルールは、**実際に予約ページで空室と1部屋総額を確認できた宿だけを表示する**ことです。確認できていない宿・料金は表示しません。

## 使い方

### ローカルで確認する

ファイルをブラウザで直接開く（`file://`）と動きません。HTTP サーバーを通して開いてください。Node.js 20 以上（npm 用）と Python 3（`serve` が使う簡易サーバー）が必要です。

```sh
cd apps/kanto-stay-search
npm run serve
# ブラウザで http://localhost:8080/ を開く
```

### 画面の操作

1. チェックイン日（1泊）とエリアを選びます。大人4名・1部屋・1部屋総額10,000円以下は固定で、画面では変更できません（「条件」の欄に「固定条件」として表示）
2. 「確認済みの宿」に、**選んだ日付・エリアで、大人4名・1部屋・1部屋総額10,000円以下で確認された宿だけ**が、1部屋総額の安い順に出ます
3. 載っていない宿は「この条件で各サイトを調べる」から外部サイトで検索します

検索条件はURLに反映されます（例: `?checkin=2026-11-27`。エリアを絞ったときは `?checkin=2026-11-27&areas=kanagawa,chiba`）。URLで指定できるのもチェックイン日（`checkin`）とエリア（`areas`）だけです。0.1.0 まで使えていた `adults`・`budget` は、URLにあっても無視されます。

### テストとデータ検証

```sh
npm test            # core ロジックのテスト
npm run validate    # site/data/ の2ファイルを検証（問題があれば終了コード1）
```

### Cloudflare Pages へのデプロイ（未実施・未確認）

ビルドは不要です。Cloudflare Pages で、ビルドコマンドなし・出力ディレクトリ `apps/kanto-stay-search/site` を指定すれば静的サイトとして公開できる想定です。実際には試していません。

## 検索方式と限界

### 方式

このアプリは**予約サイトから自動で空室を取りに行きません**。次の2つで成り立っています。

1. **確認済みデータ**（`site/data/verified.json`）: 人が予約ページを開いて空室と1部屋総額（税込）を確認し、その根拠と一緒に登録した宿だけを表示します
2. **外部サイトへのリンク**（`site/data/sources.json`）: 載っていない宿を、利用者が各サイトで検索し直すための導線

### 限界（正直に書きます）

- **ライブ検索はできない**。主要な予約サイトはJavaScriptで画面を組み立てており、自動取得に対する対策もあります。この環境（静的サイト・APIキーなし・自動取得ツール）では、日付・人数を指定した空室と価格を安定して取得できませんでした。そのため「無理に自動取得する」ことはせず、確認済みデータを手で登録する方式にしました
- **網羅性はない**。登録した宿しか出ません。「載っていない＝空室がない」ではありません
- **条件は完全一致のみ**。このアプリの条件は大人4名・1部屋に固定のため、別の人数・部屋数で確認されたデータは表示しません（4名で確認した宿を2名の料金として表示することはしません）。日付が違う確認は別データとして扱います
- **24時間で「要再確認」**。確認から24時間以上経ったデータは、画面にその旨が表示されます
- **金額は確認時点のもの**。現在は変わっている可能性があります。予約前に必ず予約ページで確認してください

### 2026-11-24 に実際に試したこと（事実）

| 試したこと | 結果 |
|---|---|
| 楽天トラベルの検索ページを自動取得 | 取得エラー。確認できず |
| じゃらんnet の検索ページを自動取得 | 取得エラー。確認できず |
| Booking.com の検索ページ（日付・人数をURLに入れた）を自動取得 | ページは返ったが、日付・人数は既定値のまま（11/24〜11/25・2名）で、0件表示。条件は反映されていなかった |
| Agoda の検索ページ（日付・人数をURLに入れた）を自動取得 | トップページに戻った。条件は反映されていなかった |
| Expedia の検索ページを自動取得 | 取得エラー。確認できず |
| シェルからの直接取得（curl） | コマンド実行に承認が必要で、実行できず |
| Web リーダーで一休.com の検索ページを取得 | 取得エラー。確認できず |

→ **空室と1部屋総額を確認できた宿は0件**でした。確認できていない宿を登録するのはアプリのルールに反するため、`verified.json` は0件のままです。

### 外部サイトリンクの3種類と現状

| 種類 | 意味 | 現在の登録数 |
|---|---|---|
| 条件を引き継ぎ（確認済み） | URLで日付・人数が引き継がれることを実際に開いて確かめた | **0** |
| 条件の引き継ぎは未検証 | URLに条件を入れるが、引き継がれるかは確かめられていない | 1（Booking.com） |
| 条件は手入力 | トップページを開く。サイト内で入力してもらう | 3（楽天トラベル・じゃらんnet・Agoda） |

注意: 国内の予約サイトでは**1人あたりの料金**で表示されることがあります。4名1室の合計額（税込）かどうかを、必ずサイトの表示で確かめてください。

## データの追加方法

### 確認済みの宿（`site/data/verified.json`）

ブラウザで予約ページを開き、条件（日付・大人4名・1部屋・1部屋総額10,000円以下）を指定して空室と「1部屋・1泊・税込」の合計額を確認してから、`entries` に1件追加します。

| 項目 | 内容 |
|---|---|
| `id` | 重複しない識別子 |
| `hotelName` | 宿名 |
| `areaId` | `tokyo` / `kanagawa` / `chiba` / `saitama` / `ibaraki` / `tochigi` / `gunma` / `shizuoka-east` のどれか |
| `location` | 表示用の所在地（例: `静岡県熱海市`） |
| `roomType` | 部屋タイプ（表示されたとおりに） |
| `planName` | プラン名（表示されたとおりに） |
| `priceTotal` | 1部屋・1泊・税込の合計額（整数・円）。1人あたりは登録不可。**10,000円以下**のものだけ登録してください（超えるものは検証では弾かれませんが、画面に出ません） |
| `priceBasis` | 固定値 `perRoomStayTaxIncluded` |
| `meal` | `{ "code": "none" / "breakfast" / "dinner" / "2meals", "label": "表示用の文言" }` |
| `cancellation` | `{ "text": "キャンセル条件" }`。確認できていないなら「未確認」 |
| `conditions` | 確認時の条件 `{ "checkin", "checkout"（翌日）, "adults", "rooms" }`。`adults` は **4**、`rooms` は **1** にしてください（画面に出るのは大人4名・1部屋で確認したものだけです。4以外の人数は検証では弾かれませんが、表示されません） |
| `sourceLabel` | 確認したサイト名 |
| `planUrl` | 確認した予約ページの `https://` のURL |
| `checkedAt` | 確認日時。タイムゾーン付き（例: `2026-11-27T19:05:00+09:00`） |
| `evidence` | 確認の根拠。画面に出た文言（例: 「1室1泊 9,800円（税込）」） |

例（**架空のデータです。実際の宿ではありません**）:

```json
{
  "id": "example-001",
  "hotelName": "サンプル旅館",
  "areaId": "shizuoka-east",
  "location": "静岡県熱海市",
  "roomType": "和室10畳",
  "planName": "素泊まりプラン",
  "priceTotal": 9800,
  "priceBasis": "perRoomStayTaxIncluded",
  "meal": { "code": "none", "label": "素泊まり（食事なし）" },
  "cancellation": { "text": "未確認" },
  "conditions": { "checkin": "2026-11-27", "checkout": "2026-11-28", "adults": 4, "rooms": 1 },
  "sourceLabel": "楽天トラベル",
  "planUrl": "https://travel.rakuten.co.jp/HOTEL/0000/0000.html",
  "checkedAt": "2026-11-27T19:05:00+09:00",
  "evidence": "予約ページに「1室1泊 9,800円（税込）」と表示されていた"
}
```

必須項目が足りないデータ・1人あたり料金のデータは、画面に出さずにコンソールへ警告を出します。

### 外部サイト（`site/data/sources.json`）

| 項目 | 内容 |
|---|---|
| `id` / `label` | 識別子と表示名 |
| `homeUrl` | トップページ（`https://` のみ。必須） |
| `areaIds` | 対象エリア。空配列なら全エリア |
| `searchUrlStatus` | `verified`（引き継ぎを確認済み）か `unverified`。既定は `unverified` |
| `searchUrlTemplate` | URLの雛形。`{checkin}` `{checkout}` `{adults}` `{rooms}` `{q}` を使える。`null` なら「条件は手入力」になる |
| `areaQueries` | エリアごとの検索語（`{q}` に入る）。指定したエリアごとにリンクが1つずつできる |
| `note` | 画面に出る注記 |

`verified` にするのは、ブラウザで実際に開いて日付・人数が引き継がれることを確かめてからにしてください。楽天トラベル・じゃらんnet のURL形式は未確認のため、現在は `searchUrlTemplate: null`（トップページへのリンク）です。
