# 事例カードのフォーマット

他人のMuseと「Museに作らせた事例」を交換するための、カード1枚の共通フォーマットです。

- カード1枚: [`case-card.schema.json`](case-card.schema.json)（JSON Schema draft-07）
- 受け渡し用の入れ物（パック）: [`card-pack.schema.json`](card-pack.schema.json)
- 検証: `node tools/validate-data.js`（アプリのフォルダで実行。自前の検証スクリプトがこのスキーマと同じルールでチェックします。外部の npm パッケージは不要です）

## カードの項目

| 項目 | 必須 | 型・制限 | 内容 |
|---|---|---|---|
| `id` | 必須 | 文字列・1〜64字。`^[a-z0-9](?:[a-z0-9-]{0,62}[a-z0-9])?$` | カードの識別子。半角小英字・数字・ハイフン。同じ id のカードは1つだけ持つ（重複は読み込み時に弾かれる） |
| `displayName` | 任意 | 文字列または null・40字まで | 表示名。匿名にするなら null または省略。画面には「匿名」と出る |
| `artifactName` | 必須 | 文字列・1〜80字 | 作ったものの名前 |
| `tagline` | 必須 | 文字列・1〜140字 | ひとこと説明 |
| `category` | 必須 | 次のうち1つ | アプリ／Webサイト／ツール／ゲーム／記事・文章／画像・動画／データ／調査・レポート／その他 |
| `tech` | 必須 | 文字列の配列・1〜8個（各1〜30字） | 使った技術 |
| `link` | 任意 | 文字列または null・500字まで・`https://` で始まる | 成果物の公開URLなど。省略可 |
| `learning` | 必須 | 文字列・1〜140字 | ひとこと学び |
| `createdAt` | 必須 | `YYYY-MM-DD` | 作成日。実在する日付であること（2026-02-30 は弾く）。未来日は警告 |

上記以外の項目はエラーになる（`additionalProperties: false`）。形式を将来に渡って安定させるためです。

## 入れ物（カードパック）の項目

| 項目 | 必須 | 内容 |
|---|---|---|
| `format` | 必須 | 固定値 `"muse-surechigai-pack"` |
| `packVersion` | 必須 | 現在は `1` |
| `exportedAt` | 任意 | 書き出し日時（ISO 8601） |
| `note` | 任意 | ひとこと注記（200字まで） |
| `sample` | 任意 | サンプル（架空のカード）パックのとき `true`。受け取った側で「サンプル」バッジが付く |
| `cards` | 必須 | カードの配列（1〜50件・id の重複禁止） |

サイトは、パックのほかに「カード1枚だけのオブジェクト」「カードの配列」も読み込めます。書き出すときは必ずパックの形になります。

### パックの例

```json
{
  "format": "muse-surechigai-pack",
  "packVersion": 1,
  "exportedAt": "2026-11-25T09:00:00+09:00",
  "note": "サンプルパックです。カードはすべて架空のものです",
  "sample": true,
  "cards": [
    {
      "id": "example-001",
      "displayName": null,
      "artifactName": "サンプル作品名",
      "tagline": "何ができるかがひとことで分かる説明文。",
      "category": "ツール",
      "tech": ["HTML", "CSS", "JavaScript"],
      "link": null,
      "learning": "この事例で得た気づきをひとことで。",
      "createdAt": "2026-11-25"
    }
  ]
}
```

## 個人情報を含めない設計

このフォーマットは、**カード単体で人を特定できない**ことを設計方針にしています。

- 実名・生年月日・住所・メールアドレス・電話番号などの項目は**存在しない**（スキーマに項目として用意していない＝書けない）
- `displayName` は任意で、書くならハンドルネーム・チーム名など。null なら匿名表示
- `link` は `https://` のみで、成果物そのものの公開URLを想定。SNSのプロフィールなど個人を特定するページは貼らない
- `id` に氏名やアカウント名を使わない（アプリ名・作品名のスラッグか、ランダムな文字列にする）
- 交換にあたり、やり取りするのはこのカードだけ。相手に自分の環境の情報やファイルが勝手に送られることはない（書き出しは明示的にボタンを押したときだけ）

カードに自由記述欄（tagline・learning・note）があるため、**そこに個人情報を自分で書き込むことは防げません**。交換に出す前に、書いた本人が確認するのがルールです。

## 検証のやり方

```sh
cd apps/muse-surechigai
node tools/validate-data.js                          # site/data/ の2ファイルを検証
node tools/validate-data.js 渡されたパック.json       # 受け取ったファイルも検証できる
node --test tests/                                   # 検証ロジック自体のテスト
```
