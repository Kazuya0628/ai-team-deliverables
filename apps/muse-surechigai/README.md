# muse-surechigai

他人のMuseと「Museに作らせた事例」を、**ニンテンドーDSのすれ違い通信**のように交換する仕組みの試作です。事例を「カード」にして持ち歩き、相手と交換すると**すれ違い成立**。集まったカードは「プラザ」に並びます。

- バージョン: 0.1.0（試作）（`package.json` と同じ）
- 状態: 開発中
- 最終更新: 2026-11-25

## 目的

AIチームがMuseに作らせたもの（アプリ・調査・文章など）は、そのままにすると自分たちのフォルダの中で終わります。**「うちのMuseが作ったもの」を他の人のMuseの作例と気軽に交換できたら、素材として見返せるし、ネタの種になる**——という考えから、まず交換の形式（カード）と流れ（書き出す→読み込む→すれ違い成立）を試作しました。

このバージョンは**静的サイト＋手動インポート**です。インターネット越しの自動交換はしません（→「将来の設計案」）。

## 仕組みの全体像

| 部品 | 中身 |
|---|---|
| カードの形式 | `schema/case-card.schema.json`（JSON Schema）。1カード＝1事例 |
| 受け渡しの形 | `schema/card-pack.schema.json`。カードを1ファイルに束ねた「パック」 |
| 自分のカード | `site/data/my-cards.json`（APPS.md と apps/kanto-stay-search の実績から作成。実データ） |
| 相手カードのサンプル | `site/data/samples.json`（**サンプル・架空のカード2枚**。流れを確かめるための同梱物） |
| サイト | `site/`（Cloudflare Pages にそのまま置ける静的サイト。ビルド不要） |
| 検証 | `tools/validate-data.js`（Node 20以上・外部パッケージ不要）。カードの検証ロジックはサイトと共通（`site/assets/validator.js`） |

すれ違いの流れ:

1. **書き出す**: サイトの「すれ違い」タブで自分のカードをJSONパックとしてダウンロードし、相手に渡す
2. **読み込む**: 相手から渡されたJSONを読み込む。検証を通った新しいカードだけが取り込まれる
3. **すれ違い成立**: 取り込まれたカードはプラザに並び、「いつ・誰のカードか」が履歴に記録される

相手がいない場合は、同梱の**サンプルカード（架空・2枚）とのすれ違いを体験**できる。履歴には「サンプル」バッジが付く。

## カード形式の仕様

詳細は [`schema/README.md`](schema/README.md)。要約:

| 項目 | 必須 | 内容 |
|---|---|---|
| `id` | ✔ | カードの識別子。半角小英字・数字・ハイフン（64字まで）。重複したカードは1つしか持てない |
| `displayName` | － | 表示名。省略か null で匿名 |
| `artifactName` | ✔ | 作ったものの名前（80字まで） |
| `tagline` | ✔ | ひとこと説明（140字まで） |
| `category` | ✔ | アプリ／Webサイト／ツール／ゲーム／記事・文章／画像・動画／データ／調査・レポート／その他 |
| `tech` | ✔ | 使った技術（1〜8個） |
| `link` | － | 公開URL（`https://` のみ）。省略可 |
| `learning` | ✔ | ひとこと学び（140字まで） |
| `createdAt` | ✔ | 作成日（`YYYY-MM-DD`。実在する日） |

**個人情報を含めない設計**: 実名・メールアドレス・住所・個人を特定するURLなどの項目はスキーマに存在しない（書けない）。`displayName` は任意・匿名可。ただし自由記述欄に自分で個人情報を書き込むことは防げないため、**交換に出す前に書いた本人がカードを確認する**のがルールです。

## 使い方

### ローカルで開く

`file://` で直接開くと動きません（fetch と ES モジュールの制約）。HTTP サーバー経由で開いてください。

```sh
cd apps/muse-surechigai
npm run serve
# ブラウザで http://localhost:8081/ を開く
```

### 画面

| タブ | 内容 |
|---|---|
| わたしのカード | 自分の実績カードの一覧（`site/data/my-cards.json`） |
| プラザ | 集まったカードを並べて眺める画面。カテゴリで絞り込み可。バッジ: `自分`（青）／`ゲット`（緑）／`サンプル`（茶・点線） |
| すれ違い | ①自分のカードをJSONで書き出す ②相手のJSONを読み込む。サンプルとの体験ボタンもここ |
| 履歴 | いつ・誰のカードとすれ違ったかの一覧。受け取ったカードと履歴は**このブラウザのlocalStorageにだけ**保存される |

読み込みに成功すると「すれ違い成立！」のバナーが出て、新しいカードだけがプラザと履歴に追加されます。すでに持っている id のカードは「すでに所持」として数えられ、二重には入りません。

### 検証とテスト

```sh
npm run validate                 # site/data/ の2ファイルを検証（エラーがあれば終了コード1）
node tools/validate-data.js 受け取った.json   # 相手からもらったファイルも検証できる（--strict で警告も失敗扱い）
npm test                         # 検証ロジック（validator.js）のテスト
```

### Cloudflare Pages へのデプロイ

ビルドは不要です。kanto-stay-search と同じ構成で、ビルドコマンドなし・**出力ディレクトリ `apps/muse-surechigai/site`** を指定すれば公開できます（デプロイ自体は未実施）。

## 限界（正直に書きます）

- **交換は手動**。JSONファイルを人間が受け渡す。自動ですれ違う仕組みはこのバージョンにない
- **カードの中身は書いた人任せ**。検証は形式（項目・字数・URLの形）だけ。`tagline` や `learning` の中身の正しさ、`link` 先の内容までは確認しない
- **なりすましは防げない**。`displayName` は誰でも書ける。カードは署名つきではない
- **id の重複は「後から来た方を弾く」だけ**。名前空間（作成者ごとのプレフィックス強制など）はない。別々の人がたまたま同じ id を付けると、先に持っていた側しか残らない
- **履歴・受け取ったカードは端末ローカル**。localStorage を消すと履歴は戻らない。ブラウザを変えると引き継がれない
- **サンプルは架空**。`site/data/samples.json` の2枚は実在しないMuse・作品の例。実在の誰かの作品ではない

## 将来の設計案（自動すれ違いにする）

今回の「カード形式」と「書き出し→読み込み→成立」の流れを保ったまま、受け渡しを自動化する案です。

1. **共有ボード（プラザサーバー）を置く**
   - Cloudflare Workers + KV / D1 などで、**カードパックを投稿できる共有ボード**を1つ用意する
   - 投稿は「パックのJSON＋任意の取得用スラッグ」。認証は不要にせず、少なくとも投稿時のワンタイムトークンか、リポジトリへのPR経由にする（なりすまし対策）
   - ボードは閲覧専用の静的API（GET）として公開し、誰のカードでも取得できるようにする
2. **各Museが定期取得する**
   - 各チームのClaude Codeに「定期的にボードを見て、新しいカードを自分のプラザに取り込む」タスクを渡す（cronまたは定期チェックに組み込む）
   - 取り込みは今回作った `parseImport`（検証＋重複除去）をそのまま使う
   - 「いつ・誰のカード」は履歴に自動記録 → **すれ違い成立の通知**が出る
3. **プッシュ型の交換（すれ違いらしさ）**
   - ボードに「交換希望」の印を付け、双方が互いのパックを取得し合えたら成立、という形にすると、DSのすれ違い通信（互いに持ち寄ったデータを交換）に近くなる
   - まずは「ボード公開 → 相手が取得」の片方向から始めるのが現実的
4. **プライバシーの維持**
   - ボードに載るのはカードだけ（今のスキーマのまま。個人情報の項目は存在しない）
   - 投稿者本人が自分のカードを削除できる窓口（ボードの管理操作）を用意する

この試作は上記の**ステップ0**（形式と流れの確定）にあたります。
