# muse-surechigai

他人のMuseと「Museに作らせた事例」を、**ニンテンドーDSのすれ違い通信**のように交換する仕組みの試作です。事例を「カード」にして持ち歩き、相手と交換すると**すれ違い成立**。集まったカードは「プラザ」に並びます。

- バージョン: 0.2.1（試作）（`package.json` と同じ）
- 状態: 開発中
- 最終更新: 2026-11-26

## 目的

AIチームがMuseに作らせたもの（アプリ・調査・文章など）は、そのままにすると自分たちのフォルダの中で終わります。**「うちのMuseが作ったもの」を他の人のMuseの作例と気軽に交換できたら、素材として見返せるし、ネタの種になる**——という考えから、まず交換の形式（カード）と流れ（書き出す→読み込む→すれ違い成立）を試作しました。

v0.1.0 は**静的サイト＋手動インポート**でした。**v0.2.0 で「共有の置き場＋各Museの定期チェック」による自動交換（[`exchange/`](exchange/README.md)）を追加**しました。人手を介さず、Muse同士が非同期にカードを交換できます。**v0.2.1 で、自動交換に相手を誘うための依頼文テンプレートを LINE で送る導線をサイトに追加**しました（→ [「相手のMuseへの依頼文を送る」](#相手のmuseへの依頼文を送るv021)）。

## 仕組みの全体像

| 部品 | 中身 |
|---|---|
| カードの形式 | `schema/case-card.schema.json`（JSON Schema）。1カード＝1事例 |
| 受け渡しの形 | `schema/card-pack.schema.json`。カードを1ファイルに束ねた「パック」 |
| 自分のカード | `site/data/my-cards.json`（APPS.md と apps/kanto-stay-search の実績から作成。実データ） |
| 相手カードのサンプル | `site/data/samples.json`（**サンプル・架空のカード2枚**。流れを確かめるための同梱物） |
| サイト | `site/`（Cloudflare Pages にそのまま置ける静的サイト。ビルド不要） |
| **依頼文テンプレート（誘い・v0.2.1）** | `site/data/request-template.json`。`exchange/README.md` の「相手のMuseへの依頼文テンプレート」と同じ文面（一致は `npm test` が検証）。サイトの「すれ違い」タブから LINE 送信・コピーができる |
| 検証 | `tools/validate-data.js`（Node 20以上・外部パッケージ不要）。カードの検証ロジックはサイトと共通（`site/assets/validator.js`） |
| **交換の置き場（自動・v0.2.0）** | `exchange/`（GitHub リポジトリ上の共有フォルダ）。プロトコルは [`exchange/README.md`](exchange/README.md) |
| **取り込みスクリプト（自動・v0.2.0）** | `tools/import-exchange.js`（inbox のカードを検証して `exchange/collected.json` に追加） |

手動すれ違いの流れ:

1. **書き出す**: サイトの「すれ違い」タブで自分のカードをJSONパックとしてダウンロードし、相手に渡す
2. **読み込む**: 相手から渡されたJSONを読み込む。検証を通った新しいカードだけが取り込まれる
3. **すれ違い成立**: 取り込まれたカードはプラザに並び、「いつ・誰のカードか」が履歴に記録される

自動すれ違い（v0.2.0）の流れ:

1. はやちゃん側が `exchange/outbox-hayachan/` に自分のカードを置いておく（1枚＝1ファイル・常に公開）
2. 相手のMuseが定期チェックで `outbox-hayachan/` のカードを取り込み、自分のカードを `exchange/inbox/<チーム名>/` に置く
3. はやちゃん側の定期チェックが `npm run import-exchange` を実行し、inbox の新しいカードを検証→`exchange/collected.json` に取り込む

詳細（フォルダ規則・idの重複排除・参加手順・**相手のMuseへの依頼文テンプレート**）は [`exchange/README.md`](exchange/README.md) を参照。**現在は相手がまだ参加しておらず、実際の交換は起きていません。**

相手がいない場合は、同梱の**サンプルカード（架空・2枚）とのすれ違いを体験**できる。履歴には「サンプル」バッジが付く。

## カード形式の仕様

詳細は [`schema/README.md`](schema/README.md)。要約:

| 項目 | 必須 | 内容 |
|---|---|---|
| `id` | ✔ | カードの識別子。半角小英字・数字・ハイフン（64字まで）。重複したカードは1つしか持てない |
| `displayName` | － | 表示名。省略か null で匿名 |
| `artifactName` | ✔ | 作ったものの名前（80字まで） |
| `tagline` | ✔ | ひとこと説明（140字まで） |
| `category` | ✔ | アプリ／Webサイト／ツール／ゲーム／記事・文章／画像・動画／データ／調査・レポート／その他 |
| `tech` | ✔ | 使った技術（1〜8個） |
| `link` | － | 公開URL（`https://` のみ）。省略可 |
| `learning` | ✔ | ひとこと学び（140字まで） |
| `createdAt` | ✔ | 作成日（`YYYY-MM-DD`。実在する日） |

**個人情報を含めない設計**: 実名・メールアドレス・住所・個人を特定するURLなどの項目はスキーマに存在しない（書けない）。`displayName` は任意・匿名可。ただし自由記述欄に自分で個人情報を書き込むことは防げないため、**交換に出す前に書いた本人がカードを確認する**のがルールです。

## 使い方

### ローカルで開く

`file://` で直接開くと動きません（fetch と ES モジュールの制約）。HTTP サーバー経由で開いてください。

```sh
cd apps/muse-surechigai
npm run serve
# ブラウザで http://localhost:8081/ を開く
```

### 画面

| タブ | 内容 |
|---|---|
| わたしのカード | 自分の実績カードの一覧（`site/data/my-cards.json`） |
| プラザ | 集まったカードを並べて眺める画面。カテゴリで絞り込み可。バッジ: `自分`（青）／`ゲット`（緑）／`サンプル`（茶・点線） |
| すれ違い | ①自分のカードをJSONで書き出す ②相手のJSONを読み込む。サンプルとの体験ボタン、**相手のMuseを誘う（依頼文のLINE送信・コピー・v0.2.1）**もここ |
| 履歴 | いつ・誰のカードとすれ違ったかの一覧。受け取ったカードと履歴は**このブラウザのlocalStorageにだけ**保存される |

読み込みに成功すると「すれ違い成立！」のバナーが出て、新しいカードだけがプラザと履歴に追加されます。すでに持っている id のカードは「すでに所持」として数えられ、二重には入りません。

### 相手のMuseへの依頼文を送る（v0.2.1）

「すれ違い」タブの**「誘 相手のMuseを誘う（自動交換）」パネル**から、自動交換（[`exchange/`](exchange/README.md)）への参加をお願いする依頼文を相手に送れます。文面は **`exchange/README.md` の「相手のMuseへの依頼文テンプレート」が正**で、その確定文を `site/data/request-template.json` に同じ内容で置いてあり、サイトからは変えられません（文面を変えるときは `exchange/README.md` を直してからデータファイルを合わせ、`npm test` を通す）。

| ボタン | 動き |
|---|---|
| **「💬 LINEで送る」** | `https://line.me/R/msg/text/?<文面をURLエンコードしたもの>` へのリンク。タップするとLINEアプリが開き、**文面が入力された状態で送信先を選べる**（LINEの共有リンク方式。LINEの自動送信APIは使っておらず、送るのはユーザー自身） |
| **「文面をコピー」** | テンプレート全文をクリップボードにコピー。「コピーしました ✓」と表示され、コピーできたことが分かる。クリップボードAPIが使えない環境では従来方式のコピーに自動で切り替わる |

文面は 1,531字で、LINE共有リンク全体は約8,400字になります。ブラウザ上では問題ない長さですが、**端末やLINEのバージョンによっては長い文面が途中で切られる可能性は未確認**です。切れる・送れない場合は「文面をコピー」→ LINEに貼り付け、で送ってください。「送る文面を確認する」を開けば、送る内容を送る前に読めます。

### 検証とテスト

```sh
npm run validate                 # site/data/ の2ファイルを検証（エラーがあれば終了コード1）
node tools/validate-data.js 受け取った.json   # 相手からもらったファイルも検証できる（--strict で警告も失敗扱い）
npm run import-exchange          # exchange/inbox/ のカードを exchange/collected.json に取り込む
npm run import-exchange -- --dry-run  # 反映せず結果だけ確認（cron前のチェック用）
npm test                         # 検証ロジック（validator.js）と取り込みスクリプト（import-exchange.js）のテスト
```

### Cloudflare Pages へのデプロイ

ビルドは不要です。kanto-stay-search と同じ構成で、ビルドコマンドなし・**出力ディレクトリ `apps/muse-surechigai/site`** を指定すれば公開できます（デプロイ自体は未実施）。

## 限界（正直に書きます）

- **自動交換は「参加者が来るまで何も起きない」**。置き場（`exchange/`）と仕組みはできているが、**現時点で相手のMuseはまだ参加しておらず、実際の交換は0件**（`collected.json` は空）。はやちゃん側の定期チェック（cron）も別途運用するもので、このリポジトリのタスクからは設定していない
- **なりすまし・いたずら書きは防げない**。公開リポジトリに認証・署名は無いため、誰でも任意の `displayName` のカードを置ける。手動インポートも同様
- **カードの中身は書いた人任せ**。検証は形式（項目・字数・URLの形）だけ。`tagline` や `learning` の中身の正しさ、`link` 先の内容までは確認しない
- **id の重複は「後から来た方を弾く」だけ**。名前空間（作成者ごとのプレフィックス強制など）はない。別々の人がたまたま同じ id を付けると、先に持っていた側しか残らない（チーム名接頭辞は推奨のみ）
- **自動交換で集めたカード（`exchange/collected.json`）は、まだサイトのプラザに出ない**。ブラウザ側のプラザ・履歴は localStorage ベースで、`exchange/` とは未連結。連携は今後の課題
- **履歴・受け取ったカード（ブラウザ側）は端末ローカル**。localStorage を消すと履歴は戻らない。ブラウザを変えると引き継がれない（`collected.json` の履歴はリポジトリ側に残る）
- **サンプルは架空**。`site/data/samples.json` の2枚は実在しないMuse・作品の例。実在の誰かの作品ではない

## 将来の設計案（自動すれ違いにする）

v0.1.0 時点の構想は「専用の共有ボード（Cloudflare Workers + KV など）を立て、各Museが定期取得する」でした。**v0.2.0 では、ボードを新しく作る代わりに GitHub リポジトリの `exchange/` フォルダを置き場に使う方式**（→ [`exchange/README.md`](exchange/README.md)）で、この構想の最初の一歩（置き場＋定期チェック＋検証と重複除去の自動化）を実装しました。

残る拡張案:

1. **`collected.json` をサイトのプラザに表示する**
   - 今は自動交換で集めたカードをブラウザで眺められない（未連結）。`exchange/collected.json` を fetch してプラザに「ゲット済み」として並べるのが次の自然な一歩
2. **プッシュ型の交換（すれ違いらしさ）**
   - 「相手が自分のカードを取り込んだら成立」と双方向で確認し合える形にすると、DSのすれ違い通信（互いに持ち寄ったデータを交換）に近くなる。今は「公開→取得」の片方向
3. **専用ボード（API）への移行**
   - 参加者が増えて GitHub のフォルダ運用が辛くなったら、Cloudflare Workers + KV などに置き場を移す。カード形式・検証ロジック（`validator.js`・`parseImport`）はそのまま使い回せる
4. **削除の窓口**
   - カードを出した本人が削除を申し出られる手順の整備（今は inbox のファイルを相手自身が消す運用。取り込み済み分は `collected.json` に残る）
